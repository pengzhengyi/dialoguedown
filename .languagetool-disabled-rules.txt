# Per-repo LanguageTool rule suppressions for `polish-tech-doc` (lt-check.py).
# One rule ID per line; `#` comments and blank lines are ignored.
# Keep this list small and conservative — only rules that are consistently
# low-value for this project's docs. Spelling false positives belong in
# `.languagetool-dictionary.txt`, not here.

# "id" is a domain term throughout DialogueDown docs — the `@id` speaker
# construct and the `Id` property — deliberately lowercase to match the syntax.
# LanguageTool's ID_CASING wants "ID"; that is wrong for this vocabulary.
ID_CASING

# "a compile" is established vocabulary here — the compiler's own docs say
# "Whether the compile ran to completion" and "a stage-boundary compile halted".
# LanguageTool's A_INFINITIVE reads `compile` as a verb and objects to the
# article; the noun is standard usage in this domain.
A_INFINITIVE

# The relative possessive — "a plan whose owner is named" — is ordinary prose in these notes,
# and this rule reads every "whose" as the contraction "who's". It has never once been right on
# this corpus, so the suggestion is noise rather than a check.
WHOSE_DT

# The notes read "The source is there so a reviewer sees it" — an independent clause joined
# without a comma, which is this documentation's established voice. The rule itself allows the
# omission when the clauses are closely connected; on this corpus it never agrees.
COMMA_COMPOUND_SENTENCE_2
